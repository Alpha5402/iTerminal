# ADR-0062: Runtime-generated cursor-position replies

- Status: Accepted
- Date: 2026-09-02
- Amends: ADR-0019, ADR-0011, ADR-0056

## Context

Real .NET 10 Console.ReadLine editing emits CSI 6 n and waits for a cursor-position reply.
The canonical headless terminal parses the query, but its generated reply was discarded.
In the user's actual Minecraft client, a backspace then stalled for about ten seconds and
the client started emitting replacement characters. A direct isolated PTY experiment stopped
the corruption growth when terminal replies were enabled. Browser resizing cannot fix this.

## Decision

The canonical parser may emit a closed cursor-position response (CSI row ; column R). The
Application receives it with the exact output revision, generation, and foreground Execution
captured at output ingestion. Viewers never originate or relay replies. Replaying snapshots,
reading Events, and reconnecting cannot create a response.

Application privately admits the generated bytes as an InputAction attributed to the fixed
`system_terminal_response` Actor, with `terminalResponse` metadata. This is not Human typing
or Agent input. Public Input APIs cannot set this provenance and continue to reject System
input. The persistence adapter revalidates the closed Actor/provenance/byte shape before its
narrow policy/Guard exemption. No arbitrary escape sequences, OSC/clipboard responses, DA,
credentials, or user-selected bytes gain that exemption.

Responses use the existing mutation lane, exact live generation/Execution check, durable
acceptance, write-attempt, one PTY write, and delivered/unknown records. No automatic replay
occurs. A stale foreground query is dropped before admission; delivery failure after admission
breaks the generation rather than retrying into a later command. The Application bounds queued
responses per Session and responses per second; overload fails the generation explicitly.

This is an additive JSON Action payload field, not a new Action kind or public RPC endpoint.
Existing ordinary System capability profiles and Human/Agent policy rules do not change.

## Security and limits

- Coordinates come from the parser at the query, not a later screen snapshot or browser.
- Responses are bounded ASCII coordinates; they never contain terminal text or secret bytes.
- The existing sensitive-output sanitizer remains fail-closed. Queries inside fully suppressed
  secret output are not observed or answered by this path; this change does not introduce a
  hidden raw-screen buffer or weaken redaction. General secret-period terminal emulation is
  outside this narrow cursor-response repair.
- Other terminal query families, arbitrary TUI compatibility, and .NET upstream behavior under
  a nonresponsive terminal are not claimed fixed.
- Runtime changes require a service restart/new live PTY; existing process state is not patched.
