# ADR-0054: Exact loopback Console ingress boundary

- Status: Accepted for M10.8
- Date: 2026-08-31

## Context

The Human Console is deliberately a loopback HTTP/WebSocket adapter, but loopback binding alone is
not a browser authorization boundary. An arbitrary web origin can send ambient requests to local
ports, DNS-rebinding names can resolve to loopback, and a WebSocket handshake can retain Runtime
observation work long after the HTTP request that created it. M5 already requires a loopback Host,
same-origin mutating requests, an HttpOnly `SameSite=Strict` cookie, and bounded outbound buffering.

The existing comparison was not an exact same-origin check. A forged HTTPS Origin could match a
plain HTTP listener by host and port, and a Host without its non-default listener port was accepted.
The server also bounded actors and each WebSocket buffer but not the number of concurrent stream
loops. Those gaps do not authorize remote deployment, but they weaken the stated trusted-local
browser boundary and make resource exhaustion unnecessarily easy.

## Decision

### Canonical listener authority

One Console process has one configured loopback hostname. It may be a `127.0.0.0/8` literal, `::1`,
or `localhost`; wildcard, DNS alias, non-loopback, and remote bind names are rejected before listen.

Every HTTP request and WebSocket upgrade must carry a syntactically pure Host authority:

- no user information, path, query, fragment, whitespace, or malformed/out-of-range port;
- hostname equal to the configured listener hostname after IP/hostname normalization;
- effective port equal to the connected local listener port. An omitted Host port means the
  protocol default (`80` for HTTP, `443` for HTTPS), not an implicit match to any local port.

Loopback aliases are not interchangeable. A process advertised as `127.0.0.1:<port>` rejects
`localhost:<port>` and other `127/8` names. This preserves one auditable authority instead of
treating every name that happens to reach loopback as trusted.

### Exact browser Origin

Every state-changing HTTP request and every WebSocket upgrade requires Origin. It must equal its
canonical URL `origin` serialization and contain only scheme and authority, with no credentials,
path, query, fragment, or normalization alias. Scheme, normalized hostname, and effective port must
exactly equal the current request authority. The plain first
release therefore rejects `https://127.0.0.1:<port>` for an
`http://127.0.0.1:<port>` listener even though host and port match.

Every HTTP `/api/*` request, including bootstrap and observation GETs, requires the non-simple
`X-ITerminal-Request: console` header. Cross-origin HTML elements cannot add it, and a cross-origin
script would require a CORS preflight that the Console does not authorize. Browser Fetch Metadata,
when present, must be `none` or `same-origin`; `same-site` and `cross-site` are rejected. GET
observation endpoints do not require Origin, but they retain Host, Fetch Metadata, request-header,
and cookie checks. Bootstrap is the sole cookie-creation endpoint and requires the request header,
preventing an ambient image/navigation loop from filling the bounded Actor registry. No bearer
token or Actor identity is accepted from a URL or browser request body.

### Bounded WebSocket admission

The Console reserves a stream slot before completing route admission. Defaults are:

- at most 64 total open or handshaking Console streams;
- at most 4 streams for one cookie-bound Human Actor;
- at most 256 live Console Actor records, retaining the existing 24-hour inactivity expiry.

An over-capacity upgrade fails with retryable HTTP `503 BACKPRESSURE` before it owns a Runtime
observation loop. A reservation not consumed by a WebSocket handler expires after five seconds, so
an aborted handshake cannot permanently consume capacity. Every handler completion or socket close
releases its slot exactly once. Limits are process-local protection for this one loopback adapter;
they are not distributed tenant quotas.

Client WebSocket messages remain bounded to 16 KiB and may contain only the strict acknowledgement
schema. The first malformed acknowledgement closes the stream with policy-violation code `1008`
instead of allowing an attacker to create an unbounded parse/error-response loop. A slow outbound
consumer still receives resynchronization and closes once its pending-send boundary exceeds 1 MiB.

### Error response boundary

Ingress rejections, invalid JSON, oversized bodies, and otherwise unknown adapter errors use fixed
messages and metadata-only details. They do not echo Host, Origin, cookie, request body, Runtime
grant, caller-supplied request ID, internal exception text, or URL query values to the client.
Request IDs are generated by the Console rather than trusted from `X-Request-Id`. The production
default keeps the Fastify logger disabled. Schema validation errors do not return raw Zod issues,
which can contain caller-controlled key names. Enabling custom request logging can expose
method/URL/Host metadata and is outside this decision; a complete repository log-secrecy audit
remains a separate M10 security slice.

## Consequences

- Browser writes and observation upgrades have one exact, testable local authority.
- Alternate loopback aliases and scheme mismatches no longer work; bookmarks and reverse proxies
  must use the configured URL exactly.
- A tab storm receives explicit backpressure rather than creating unbounded screen waits and Event
  queries.
- Console restart still loses cookie Actor records and stream counters. The Runtime Action/Event
  truth and Interaction Guard TTL remain authoritative.
- Remote/multi-user access remains unsupported even when the caller possesses a Console-to-Runtime
  grant; the browser cookie is not remote authentication.

## Not covered

- TLS termination, reverse-proxy trust, remote bind, OS-user separation, sandboxing, CORS sharing,
  or multi-tenant quotas.
- Repository-wide token/log redaction, Shell marker/path hostile-input review, command allowlists, or
  filesystem containment.
- HTTP request-rate limits. Durable Action rate limits remain PostgreSQL-authoritative, while cheap
  observation/bootstrap request-rate protection remains future work.
- Distributed stream admission across multiple Console processes.

## Rejected alternatives

- **Trust loopback binding alone:** ambient browser requests can still reach a local listener.
- **Allow every loopback Host alias:** expands the browser authority beyond the configured URL and
  weakens DNS-rebinding evidence.
- **Compare only Origin host and port:** violates the browser same-origin tuple by ignoring scheme.
- **Put a bearer token in the WebSocket query:** leaks credentials through URLs, logs, history, and
  copied links.
- **Bound only `bufferedAmount`:** limits one slow socket but not the number of active Runtime wait
  loops.
- **Silently evict an older tab:** can discard a Human's observation context without an explicit
  backpressure response.
