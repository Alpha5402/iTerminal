## Contract and observed behavior

| Scenario             | Observed result                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source and stream    | Reads only sanitized durable `terminal.pty_output` Events and their retained Artifacts. It always reports `stream=pty`; it does not inspect the lossy live byte ring, invent stdout/stderr, or remove terminal echo.                                                                                                                                                                          |
| Exact scope          | PostgreSQL binds Execution id, Session id, and generation before cursor decoding. Missing and cross-scope requests both return `EXECUTION_NOT_FOUND`; a malformed or forged cursor is reported only after an exact Execution exists.                                                                                                                                                          |
| Cursor               | The bounded base64url cursor contains version, exact scope/fingerprint, Event sequence, and byte offset only. It contains no command, output, Actor, request hash, token, path, or timestamp. A new repository instance resumed the same cursor and returned identical bytes/cursor. This proves persistence-process reopen, not a live Runtime daemon restart.                               |
| Paging               | Default byte budget is 8 KiB and maximum 64 KiB. Unicode pages split inside a multibyte character and reassembled by `Buffer` exactly. A request ending exactly at the final Event reports `hasMore=false`; a 65th-row probe reports `hasMore=true` without returning unbounded per-Event metadata.                                                                                           |
| Live tail            | While a deterministic >2 MiB PTY producer was held running, the official MCP client reached the current durable tail with `hasMore=false`, `executionState=RUNNING`, and `persistenceLag=possible`. Thus output silence was not presented as completion.                                                                                                                                      |
| Terminal waterline   | After release, the terminal response reported `persistenceLag=none`. The durable maximum output Event sequence was lower than the `execution.completed` sequence, matching the Application flush-before-terminal ordering.                                                                                                                                                                    |
| Event retention      | A fresh read after deleting the accepted/prefix Events reported `event_retention` and the exact minimum retained sequence while returning only the retained suffix. A pre-deletion nonzero cursor then failed `RESYNC_REQUIRED` instead of silently advancing. Event gaps use the ordinary `nextCursor` and never claim an Artifact `resumeCursor`.                                           |
| Artifact retention   | Missing and expired output Artifacts are distinct `artifact_missing` and `artifact_expired` gaps. No bytes after that Event are concatenated into the response. `nextCursor` covers only returned prefix bytes; the separate `resumeCursor` must be deliberately adopted to continue after the unavailable Event.                                                                             |
| Forgery              | Canonical base64url cursors modified to use a future sequence, non-output anchor, out-of-range offset, or foreign Session all fail `RESYNC_REQUIRED` for an exact Execution. Sending the foreign cursor with a cross-scope Execution request remains the non-disclosing `EXECUTION_NOT_FOUND`.                                                                                                |
| Bounded wire         | At most one chunk and 64 KiB decoded content are accepted. Canonical schemas correlate base64 length, require continuation cursors where needed, enforce active=`possible` and terminal=`none`, bound every field, and reject JSON responses above 96 KiB.                                                                                                                                    |
| Capability and grant | Durable owners advertise `execution.output.read.v1`; no-database owners do not. Router unscoped capabilities advertise the implemented route while scoped capabilities remain the exact owner's response. The composed local stack used a signed grant containing `execution.output.read` to read real durable output. This operation grant is not a per-Session Actor ACL; that remains F03. |
| Read lifecycle       | Application reads allocate no Action/Event/sequence and perform no PTY write. Closing the first MCP client after reaching a running durable tail did not release the Execution: a fresh MCP client observed the same Execution still `RUNNING`, then continued the old cursor after explicit fixture release.                                                                                 |

`hasMore` describes only bytes currently available in one continuous durable window. It does not
mean that the Execution is terminal, and an Artifact gap is not represented as ordinary
`hasMore`. PostgreSQL range-reads an Artifact page, but PostgreSQL TOAST may internally
fetch/decompress more of an immutable row; B02 does not claim zero-copy object storage.

## Evidence level and limits

Result: PASS at L2 for B02. L1 covers canonical transport invariants, Application non-mutation,
signed operation grants, exact-owner routing and capability gating, cursor forgery, retention
classification, byte boundaries, scan/response budgets, and repository reopen. L2 covers a real
daemon-owned PTY, >2 MiB output, PostgreSQL Event/Artifact truth, running and terminal waterlines,
MCP client restart, signed local-stack routing, and byte-for-byte reconstruction through the
official MCP tool.

This is not L3: no browser-driven Human Console plus external Agent workflow ran. It is not L4:
there was no pressure/soak, concurrent retention race injection, PostgreSQL failover, mixed-version
rolling upgrade, multi-host, Linux, Windows/ConPTY, or object-store exercise. B02 does not merge a
live ring tail, add stdout/stderr attribution, add per-Session ACLs, or implement B03/B04/B06.
Because the read is immediate, the L2 lifecycle case covers MCP-client disconnect between reads
while the Execution remains running; it does not artificially delay a database query solely to
cancel an in-flight response frame.
