## Contract and observed behavior

| Scenario             | Observed result                                                                                                                                                                                                                                                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Durable cache        | Only a terminal Action whose terminal durable write has returned successfully becomes eligible. Execute additionally requires a terminal Execution. FIFO pruning removes linked Action, Execution, idempotency binding and byte accounting together. Active/unpersisted facts remain pinned.                                                                      |
| Durable replay       | After a terminal fact was evicted under a one-entry budget, replay of the original Execute key returned the B06 durable Action/Execution ids and the fake executor observed no second command. Changed request behavior remains B06's conflict contract.                                                                                                          |
| Memory-only capacity | Action and Execution JSON-byte estimates both count toward the history budget. Ordinary Execute/Input/Secret/Resize admission stops before sequence allocation or PTY side effects when it would consume the Control reserve. Control can consume the finite reserve; after it is full, only existing reads/waits and close remain available.                     |
| Event retention      | Each generation retains a strict entry/byte-bounded suffix. Discard clears each array slot before advancing `discardedThrough`; an oversized single Event may leave an empty suffix. Fresh reads expose `gap=true`; a nonzero cursor before the floor receives `RESYNC_REQUIRED`; the exact acknowledged floor continues normally.                                |
| Event wire boundary  | RPC validates a strict Event envelope, bounded canonical Actor, at most 128 payload fields, at most 64 KiB serialized payload per Event, at most 500 Events and 4 MiB serialized page, a single ordered Session generation, retention-floor correlation, and `nextAfter` correlation. Event payload semantics and legacy Event fields are otherwise unchanged.    |
| Execute cleanup      | Completion first notifies registered V2 waiters, then releases dispatch, started and completion map entries. A later wait reads the terminal Execution snapshot. Concurrent waiter cancellation removes only that waiter and sends no Control; close wakes the survivor as terminal `UNKNOWN` and all waiter/transient counts return to zero.                     |
| Stress diagnostics   | Under 2,000 durable terminal Input Actions, the configured cache stayed at 8 terminal facts plus one pinned active Execute, 32 Events and one Execution. RSS changed from 84,869,120 to 147,128,320 bytes: a +62,259,200-byte observation, below the test's 128 MiB guard. This is a bounded-run observation, not proof of a GC plateau or absence of every leak. |
| Real daemon          | A real PTY completed one command, held another Execution active, rejected the next ordinary Action at capacity, accepted one reserved Control, and still closed the Session. Close made the active outcome `UNKNOWN` rather than inventing completion. Events stayed at or below six with an explicit gap and all Execute transient counts returned to zero.      |

The diagnostics inventory also reports approvals and active/rebuildable resources. ADR-0075 is
explicit that B07 does not invent eviction rules for durable Approval, root-Session replay, fork,
checkpoint, Actor, PostgreSQL tombstone or database history facts.

## Evidence level and limits

Result: PASS at L2 for the scoped B07 behavior. L1 proves bounded and correlated data structures,
pre-side-effect backpressure, active/unpersisted pins, durable replay after eviction, terminal
cleanup, cancellation independence, wire bounds, and pressure diagnostics. L2 proves the capacity,
Control, close and Event-gap path with a real Runtime daemon and zsh PTY, plus compatibility with a
real isolated PostgreSQL fixture and official MCP stdio path.

This is not L3: no browser Human Console plus external Agent workflow ran. It is not L4: there was
no long-duration soak, forced-GC heap profiling, multi-owner pressure, database failover, hostile
payload campaign, Linux or Windows/ConPTY run. RSS is allocator/GC-dependent and the observed delta
is not a production SLO. Approval/Actor/root-Session/fork/checkpoint retention, PostgreSQL tombstone
capacity and hard process memory limits remain outside B07 as listed in ADR-0075.
