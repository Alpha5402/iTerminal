## Public contract and security observations

| Scenario            | Observed result                                                                                                                                                                                                                                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scope consistency   | PostgreSQL matches Artifact id, Session id and generation in one query. Wrong Session/generation and a missing id return the same non-disclosing `not_found` shape.                                                                                                                                                         |
| Grant boundary      | `artifact.read` is an Actor-free observation operation protected by the signed RPC operation allowlist. A grant without that operation remains `POLICY_DENIED`; it is not converted to `not_found`. This is not a per-Session Actor ACL, which remains F03 work.                                                            |
| Bounded ranges      | Omitted `maxBytes` returns at most 8 KiB; the maximum accepted value is 64 KiB. Requests above 64 KiB are rejected, offset equal to total is empty EOF, and offset beyond total is `INVALID_REQUEST`. A `Number.MAX_SAFE_INTEGER` offset is classified by the contract rather than overflowing a PostgreSQL `integer` cast. |
| Wire integrity      | The canonical result bounds base64 expansion and verifies decoded length, `nextOffset = offsetBytes + returnedBytes`, total bounds and EOF consistency. Stored SHA-256 is not exposed.                                                                                                                                      |
| UTF-8 boundaries    | Base64 pages reconstruct 7 KiB and 1 MiB Chinese/emoji fixtures byte-for-byte. MCP emits text only after fatal UTF-8 decoding; a one-byte split inside a multibyte character returns `textStatus: unaligned_utf8` and no partial/replacement text.                                                                          |
| Real MCP path       | A durable daemon produced more than 4 KiB of real PTY output. Artifact refs came from unchanged Events; official MCP `artifact_read` paged those refs and the combined inline/artifact bytes exactly equalled the canonical observed Execution output.                                                                      |
| Expiry and outage   | Exact-scope expired storage returns typed `expired`. Closing a real PostgreSQL durability pool makes a fresh RuntimeService return retryable `unavailable/durability_unavailable`, not `not_found`. Missing owner routes return `not_found`; an unavailable exact owner returns `unavailable/owner_route_unavailable`.      |
| Secret period       | A 28 KiB raw sensitive-period sentinel produced zero Artifact refs and zero Artifact rows for its Execution, and was absent from durable Event/Artifact content. A fabricated read returned `not_found`; there is no raw/unredacted option.                                                                                 |
| Capability accuracy | A durable daemon advertises `artifact.read.v1`; a no-database daemon does not. Local gateway support is opt-in, injected Runtime composition is conservative, Router unscoped capabilities advertise its implemented route, and Router scoped capabilities remain the exact owner's response.                               |
| No mutation         | Application read allocates no Action, Execution, Event or sequence and performs no PTY write. Typed read outcomes do not cause Runtime state transitions.                                                                                                                                                                   |

The submitted Session id is a durable lookup scope, not proof of caller ownership. Existing
ADR-0056 operation grants authorize the read operation; B01 does not claim a caller holding such a
grant has separately proven membership in a particular Session.

PostgreSQL returns `substring(bytea)` so the Node.js client and transport materialize only the
bounded page. PostgreSQL TOAST may internally fetch/decompress more of the immutable row; this is
honestly retained as storage read amplification, not described as object-store or zero-copy
streaming.

## Evidence level and limits

Result: PASS at L2 for B01. L1 covers canonical schemas, result invariants, Application
non-mutation, operation-grant denial, Router classifications, capability gating and non-disclosing
scope mismatches. L2 covers retained/expired PostgreSQL rows, 7 KiB and 1 MiB byte reconstruction,
real PTY output through unchanged Events and official MCP paging, a real closed durability pool,
and durable secret-period exclusion.

This is not L3: no browser-driven shared Human Console plus external Agent workflow ran. It is not
L4: there was no hostile grant fuzzing, pressure/soak, multi-host, rolling mixed-version, Linux,
Windows/ConPTY or object-store exercise. B01 does not add per-Session Actor ACLs, delete tombstones,
streaming object storage, or B02 cursor/tailing semantics. Existing sanitized Artifact row limits
and retention policy remain unchanged.
