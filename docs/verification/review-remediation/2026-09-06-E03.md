## Command and method

`pnpm exec tsx scripts/benchmark-remediation.ts --output=docs/verification/review-remediation/artifacts/performance.json`

Both executor variants use the current ring/projection; only the per-poll 16 KiB scratch allocation differs. Workloads are idle (1.5 seconds), 100×1 KiB delayed output, 1 MiB high throughput, and four simultaneous delayed-output Sessions. SHA checks enforce exact fixture payload; completion start/end ordering is checked per Session. Python temporarily disables OPOST for byte-exact framing and restores it. Parent-process CPU excludes the child Python process. Projection latency is callback-to-snapshot, not browser paint.

## Decision and correctness

Preserve the existing 64 plain snapshot history and applied-version ordering (ADR 0021/0079); do not change FIFO protocol or polling frequency. Control-protocol, terminal-response and screen tests plus full regression appear in [final verification](2026-09-06-final-verification.md). Level L2, with only the exact local workloads above.

## Not proven

High-throughput projection P95 remains about 1.4 seconds. Four-Session CPU did not improve in this sample. Single samples have scheduler/GC variance and are not statistical performance guarantees; no absolute timing threshold is enforced. No deadlock occurred in these bounded workloads, which is not starvation freedom or a production soak claim.
