# E02 fixed byte ring — 2026-09-06

## Revision and environment

Candidate: integration diff after `5c59a49ed034bb3d6e59231a4c3e93f20128d4ea`, macOS arm64 Apple M5, Node v24.15.0. Temporary instrumented source files and owned PTYs are cleaned by the scripts. Raw JSON remains in ignored local artifacts; the measured values are retained here.

## Measurement

Command: `pnpm exec tsx scripts/benchmark-remediation.ts --output=docs/verification/review-remediation/artifacts/performance.json`.

Same 2 MiB capacity, 8192 appends of 1 KiB: baseline 410.64 ms, fixed ring 1.03 ms. Instrumented append allocation at the ring storage/concat sites was 15,039,725,568 bytes versus 2,097,152 bytes; each final snapshot was 2,097,152 bytes and SHA-256 matched `6932fd31e5daf4739b9fa78ff777b2831b0995cc1d0b0093cac80601902013bc`.

The fixed storage preserves absolute byte offsets, oversized tail retention and independent returned snapshots. Random reference-buffer tests and execution-output tests are included in [final verification](2026-09-06-final-verification.md). Level L1 plus a reproducible microbenchmark.

## Not proven

This deliberately isolates the prior repeated-concat cost. Allocation counters are named sites, not whole-process allocations or GC totals. One microbenchmark does not establish overall product speed or universal latency. Unicode clipping remains a byte-cursor/gap contract in the decoding layer.
