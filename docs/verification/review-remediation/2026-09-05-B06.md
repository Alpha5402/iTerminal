## Contract and observed behavior

| Scenario               | Observed result                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public result          | Exact `sessionId`/`generation` and authenticated Actor scope plus Action idempotency key or Execution id returns `full` (`live` or `durable`), `compacted` with `retention.state=expired`, non-disclosing `not_found`, or typed retryable `unavailable`. Command, payload, request hash, Actor, output, path and token fields are absent.                                   |
| Live authority         | Memory wins for an exact live fact. A durable-only active Action/Execution returns `unavailable`; no durable row creates a Session, executor, completion promise, Shell, or READY state. Terminal facts remain readable after daemon restart.                                                                                                                               |
| Artificial eviction    | A terminal Execute was queried before and after hiding its in-memory Action/Execution; the public fact stayed equal while source changed from `live` to `durable`. Replaying the same key returned the original ids and produced one Shell command.                                                                                                                         |
| All Action replay      | Execute, Input, Control, Secret Input and Resize all call the common durable replay gate before id/sequence allocation or PTY side effects. Artificially evicted Input/Control replay returned original Actions with zero second write/control; changed payloads conflicted. Memory Secret Input/Resize replay rejected the same Actor id with changed immutable principal. |
| Cross generation       | Admission lookup searches Session/Actor/key without a generation filter. A key held by another generation returned non-retryable `IDEMPOTENCY_KEY_REUSED` before reservation or PTY write. Public history lookup independently requires the exact generation and returns no fact for a wrong generation.                                                                    |
| Retention/tombstone    | Retention writes a terminal-only tombstone and deletes the normalized Action in one transaction. Exact Action id/hash conflict leaves the source Action intact. Matching and changed tombstones cannot create a new Execution. Tombstone foreign keys restrict Session-generation deletion and do not cascade away anti-replay evidence.                                    |
| Actor scope            | PostgreSQL verifies the complete immutable Actor identity before exact history selection. Public Application lookup maps identity mismatch to the same `not_found` shape as missing; durable admission treats identity drift as a conflict before side effects.                                                                                                             |
| Failure classification | A real PostgreSQL table lock plus a 50 ms query/statement budget produced `durability_timeout`, not `not_found`. Other backend failures remain `durability_unavailable`; Router route absence/unavailability is separately `not_found`/`owner_route_unavailable`.                                                                                                           |
| Compatibility          | Legacy `execution_get` remains memory-only and A06 `action_lookup` keeps its existing found/expired/not-found/unavailable union. Direct no-database owners do not advertise `history.lookup.v1`; Router advertises only its routing contract and scoped capabilities remain the exact owner response.                                                                       |

ADR-0056 operation grants protect the new read at the transport boundary. These tests prove grant
allowlisting and exact Actor/Session/generation scope consistency; they do not claim the later F03
per-Session ACL design.

## Evidence level and limits

Result: PASS at L2 for the scoped B06 behavior. L1 covers the public result union, protocol
bounds/correlation, artificial memory eviction, replay and conflict matrices across Action types,
exact routing, capability/grant gating, timeout classification, and transactional tombstone
constraints. L2 covers real PostgreSQL retention/restart truth, a real PostgreSQL statement timeout,
official MCP, Runtime daemon restart, and a real daemon-owned zsh PTY.

This is not L3: no browser Human Console plus external Agent workflow ran. It is not L4: no soak,
large-scale compaction pressure, PostgreSQL failover, mixed-version rolling fleet, multi-host,
Linux, Windows/ConPTY, or adversarial capacity exercise ran. B06 deliberately does not implement
B07's eviction budgets or memory-only capacity rejection. Tombstones are retained indefinitely
because the public idempotency key has no authenticated epoch; their eventual capacity policy
requires a separate decision.
