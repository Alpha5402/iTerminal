## Implemented behavior

- `CreateExecutorOptions` binds every Executor to one opaque Executor identity plus the exact
  Session ID and generation. The lifecycle callback reports a stable reason and optional node-pty
  Shell `exitCode`/`signal`; it never changes domain or durable state itself.
- Application receives lifecycle notifications in the existing per-Session mutation lane. It
  ignores duplicate, stale-generation, and wrong-Executor notifications.
- Active close removes the Application binding before closing the Executor, so the resulting child
  exit cannot create `session.broken` after `session.closed`.
- A current READY Shell exit detaches the Executor, unregisters the Guardian, rejects/finishes local
  waiters, disposes the live screen, and persists `BROKEN`. Later Execute fails before a PTY write.
- A current RUNNING Shell exit persists the Session as `BROKEN` and the Action/Execution as
  `UNKNOWN`, emits one `execution.unknown` and one `session.broken`, and does not copy the Shell
  process exit into `Execution.exitCode`.
- Startup owns the same mutation lane. An Executor lifecycle notification observed before factory
  completion causes `STARTING -> BROKEN` and no `session.shell_ready` Event.
- No path automatically rebuilds, replays a command, recovers the old Shell, or treats a database
  row as evidence that a process is alive.

## Real observations

| Scenario                                  | Observation                                                                |
| ----------------------------------------- | -------------------------------------------------------------------------- |
| READY Shell receives real `SIGKILL`       | node-pty lifecycle reached Application; Session became durable `BROKEN`    |
| Execute after READY Shell loss            | `SESSION_BROKEN`; no replacement Executor or PTY was created               |
| RUNNING `sleep 30` Shell receives kill    | completion rejected `DELIVERY_UNKNOWN`; Execution became durable `UNKNOWN` |
| Shell exit metadata                       | bounded lifecycle Event payload retained the Shell exit observation        |
| Command exit truth                        | in-memory and PostgreSQL Execution exit code remained absent/NULL          |
| Duplicate lifecycle callback              | exactly one broken transition and one active-execution settlement          |
| Wrong identity/generation callback        | current READY binding remained unchanged                                   |
| Delayed old callback after rebuild/fork   | rebuilt child remained READY with its distinct Executor                    |
| Active close followed by delayed callback | Session remained CLOSED with zero broken Event                             |
| Exit during factory startup               | creation failed in BROKEN without publishing shell-ready                   |

## Compatibility and rollback

- Existing Shell Executor factories receive additional required owner-binding/lifecycle options;
  the production and repository test factories compile against the updated port.
- Existing public HTTP/RPC/MCP schemas and error response shapes are unchanged.
- Rollback removes the lifecycle callback and Application handler, restoring the known unsafe
  behavior where an idle dead Shell may remain represented as READY.

## Not covered

- Automatic rebuild or replay, old PTY recovery, and database-derived process liveness are
  intentionally excluded.
- A02's removal of the 24-hour adapter execution timer and its complete fatal-path matrix are not
  part of A01.
- No Browser Human Console, official MCP client, Linux, Windows/ConPTY, multi-host, long-soak, or
  hostile same-user process test was run for this card.
- The existing Guardian cannot cover whole-host/kernel/Guardian failure or deliberately detached
  same-user processes; ADR-0045's boundary remains unchanged.
