## Implemented behavior

- A pending Execute no longer owns an adapter wall-clock timer. Advancing an injected scheduler
  beyond the former 24-hour limit neither rejects the promise nor closes the real executor.
- Only the Shell startup HELLO/READY waiter uses the new executor-local injected scheduler. Screen
  observation, PTY Event flush, Process Guardian, and Runtime shutdown/drain timers remain on their
  existing independent paths.
- `onWriteAccepted` records that the first node-pty dispatch write returned. It does not claim that
  the Shell consumed the bytes or that PREEXEC occurred. Existing Executors remain compatible
  because the callback is optional; observed PREEXEC/RUNNING remains sufficient uncertainty
  evidence.
- Application fatal settlement follows ADR-0067: a definite pre-write rejection becomes
  `FAILED`; an accepted write without completion becomes `UNKNOWN`; a Shell-observed result remains
  `COMPLETED`/`INTERRUPTED`.
- A fatal settlement clears pending PTY output/sensitive state, removes and closes the exact
  executor, disposes its screen, breaks the generation, and then attempts durable settlement. The
  close-triggered lifecycle callback is stale by executor identity and cannot settle twice.
- No user-configurable deadline, automatic retry/replay, automatic rebuild, or database-derived
  process liveness was added.

## Failure matrix observations

| Boundary                                       | Result                                                         | Event                         | Executor / generation observation                 |
| ---------------------------------------------- | -------------------------------------------------------------- | ----------------------------- | ------------------------------------------------- |
| Adapter rejects before dispatch write          | Action/Execution `FAILED`                                      | one `execution.failed`        | executor closed once; Session `BROKEN`            |
| Dispatch write accepted, no PREEXEC/completion | Action/Execution `UNKNOWN`; caller receives `DELIVERY_UNKNOWN` | one `execution.unknown`       | executor closed once; Session `BROKEN`            |
| PREEXEC observed, Shell later exits            | Action/Execution `UNKNOWN`; no exit code invented              | one `execution.unknown`       | A01 lifecycle cleanup remains idempotent          |
| RESULT/READY completion observed               | `COMPLETED` or `INTERRUPTED` with observed exit                | completion/interruption Event | Session returns `READY`; executor stays available |

The pre-start accepted-write case was exercised in both immediate and external dispatch. External
dispatch settled without waiting on its own mutation lane, so it did not deadlock.

## Compatibility and rollback

- Public HTTP/RPC/MCP schemas and response DTOs are unchanged.
- Existing Shell Executor implementations need not implement `onWriteAccepted`; a RUNNING/PREEXEC
  failure remains conservative `UNKNOWN`.
- Rollback restores the unsafe adapter lifetime rejection and the previous uniform `FAILED`
  settlement, which can leave a live Shell without an Application control path.

## Not covered

- User-configurable execution deadlines, scheduler/job semantics, automatic cancellation,
  auto-replay, and auto-rebuild are intentionally excluded.
- PostgreSQL persistence was not exercised for A02; existing A01 durable lifecycle and broader M8/M9
  recovery evidence remain separate historical evidence, not a result of this run.
- No Browser Human Console, official MCP client, Linux, Windows/ConPTY, multi-host, or long-duration
  run was performed.
- Host/kernel/Guardian loss and descendants deliberately escaping the fixture's process tree remain
  ADR-0045 external-fencing boundaries.
