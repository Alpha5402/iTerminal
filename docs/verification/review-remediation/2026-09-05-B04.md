## Contract and observed behavior

| Scenario                     | Observed result                                                                                                                                                                                                                                                                                                                                                                                       |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Public shape                 | The strict request carries exact `sessionId`, `generation`, and `executionId`, plus optional B02 `cursor`/`maxBytes` and B03 `waitMs`. The result contains only compact identity, state, one bounded merged-PTY byte page, optional readable text, cursor, closed gap, retention and derived next actions. It does not include command, Action, Actor, idempotency key, path, token, or exit details. |
| Budget and schema            | Output defaults/max remain 8 KiB/64 KiB and wait defaults/max remain 10,000/30,000 ms. Base64 length must equal `byteLength`; text/state/terminality/persistence-lag/next-actions are correlated. A maximum 64 KiB raw page with text omitted serialized below the 96 KiB canonical response budget.                                                                                                  |
| Composition                  | Application validates the live exact scope before cursor handling, spends exactly one B03 wait budget, then performs exactly one immediate B02 durable read. Router forwards once with the same signal and does not compose its own wait. Cancellation prevents the read and emits no Control/Input.                                                                                                  |
| State authority              | Empty output never implies completion. The later durable read supplies the public state. If a wait already observed a terminal state and the read reports an active or different terminal state, Application returns retryable `RUNTIME_UNAVAILABLE` instead of regressing to `completed=false`.                                                                                                      |
| ANSI and readable text       | Official MCP execution produced ANSI bytes. `contentBase64` decoded byte-for-byte equal to the ordered durable Event/Artifact truth and retained the ESC bytes. The convenience text rendered ESC visibly as `␛`, contained no executable ESC, and retained the real printed line `echo SAME-COMMAND-LINE`; no command-looking-line regex was applied.                                                |
| Cursor reconstruction        | A real Unicode/emoji command produced more than one 1,025-byte page. The official MCP client followed `nextCursor`, observed an `unaligned_utf8` page at a real code-point boundary, concatenated Buffers rather than decoded page strings, and reproduced the complete ordered durable bytes without loss or duplication.                                                                            |
| Finite wait                  | A real long-running command observed with `waitMs=50` returned RUNNING, `completed=false`, `persistenceLag=possible`, and `wait_for_completion`. A later observation of the same Execution returned COMPLETED; the timeout did not stop or release the PTY.                                                                                                                                           |
| UNKNOWN                      | An adapter-contract fixture returned a real canonical UNKNOWN observation. MCP preserved `completed=true`, `persistenceLag=none`, and only `lookup_original_action`; the JSON contained neither an idempotency-key field nor a manufactured command/request identity. This is L1 adapter-contract evidence, not an injected real PTY failure.                                                         |
| Sensitive period             | A Human-sensitive-input fixture caused both the supplied secret and independently generated raw sensitive-period output to reach the PTY. Official MCP observation exposed only the durable redaction notice: raw bytes, readable/structured output and duplicated MCP text contained neither sentinel.                                                                                               |
| MCP compatibility            | Every official MCP call asserted that parsed JSON text content exactly equals `structuredContent`; this deliberately preserves two equivalent protocol representations and is not claimed as token reduction.                                                                                                                                                                                         |
| Capability and compatibility | A direct daemon advertises `execution.observe.v1` only with its durable output reader; the no-database MCP path does not advertise it. Router advertises its forwarding contract, while scoped owner capability remains exact. Existing `execution_get`, wait and output-read contracts are unchanged.                                                                                                |

ADR-0056 grants protect this read operation at the transport boundary. These tests prove operation
allowlisting and exact Session/generation/Execution scope consistency; they do not claim a separate
per-Session Actor ACL, which remains F03.

## Evidence level and limits

Result: PASS at L2 for B04. L1 covers exact-scope ordering,
single-wait/single-read composition, cancellation without writes, terminal-state monotonicity,
UNKNOWN guidance without a key, response/schema budgets, capability/grant wiring, Router forwarding
and MCP dual-representation equality. L2 covers a real daemon-owned PTY/zsh, official MCP calls,
durable PostgreSQL Event/Artifact comparison, exact ANSI bytes, visible controls, command-named
output, Unicode cursor reconstruction, finite wait followed by completion, and sensitive-period
non-disclosure.

This is not L3: no browser Human Console plus external Agent workflow ran. It is not L4: no soak,
retention-gap failure injection, owner failover/restart, rolling mixed-version fleet, multi-host,
Linux, Windows/ConPTY, or adversarial pressure exercise ran. UNKNOWN is proven at Application and
official-MCP adapter-contract level rather than by killing a live fixture. MCP response duplication
is preserved and no actual model-token/call-cost result is claimed; F02 remains responsible for
that measurement. Durable historical observation after live Runtime eviction remains B06.
