# 单任务执行提示词

复制下面整段；默认执行 A01。交接下一张任务时只替换任务 ID。不要把整份计划作为“一次性全部完成”的指令交给执行模型。

```text
请在 /Users/alpha/Documents/ChatGPT/iTerminal 执行整改任务 A01。

背景：这是 Human-Agent 共用一个持久 PTY/Shell 的终端。此前只读审阅已经完成，本次是按既定方案做一张卡，不需要重新审阅全仓。

目标与先读：
1. 读取 AGENTS.md、docs/plans/review-remediation/README.md。
2. 从索引找到 A01，读取对应任务卡。仅沿卡列出的源码入口和直接调用链阅读。
3. 涉及运行语义时读取 TODO.md、docs/TERMINOLOGY.md、ADR 索引及该卡相关 ADR、最近相关验证记录；不要加载全部历史材料。
4. git status --short 确认已有工作。仓库已有大量用户未提交改动，按当前工作树修改，不用 HEAD 覆盖，不 reset/stash，不全仓格式化。

实施标准：
- 只完成 A01；检查依赖均已验收，未满足时报告具体阻塞，不擅自实现其他卡。
- 按任务卡的目标行为、步骤、验收场景和禁止范围实施。新接口名称/预算是计划要求；先检查有无既有同名实现，有则扩展，不平行造重复路径。
- 需要改变状态、顺序、持久化、ownership、安全或协议时，先写相关 ADR 再实现；这不是额外用户审批步骤。
- domain <- application <- adapters/apps；写入决策和状态转移留在 Application。UNKNOWN 不自动重放，查询 not_found 不代表原请求不会稍后到达。
- 一次只做一个局部变更，再跑对应定向测试。不要为了少写代码删除保护，也不要为假想风险扩展新平台。

验证与证据：
- 执行卡列出的失败场景和命令、pnpm typecheck、所改文件 Prettier 检查、git diff --check。阶段或提交收尾才运行 pnpm verify 与阶段真实场景。
- 实测只能创建自己的临时目录、socket、owner、Session、子进程。PG 必须是隔离测试实例的 iterminal_test；不能触碰用户运行中的数据库/会话，也不能重启用户服务。
- 环境缺失/测试 skip 不算通过。可先完成不受阻的代码和 L1；清楚标“已实现待 L2/L3 验证”，不要声称验收。
- 新增 docs/verification/review-remediation/<日期>-A01.md，记录实际命令、pass/fail/skip、证据级别、实测边界，不包含 token/secret/用户输出，不修改历史记录。
- 更新本计划索引中 A01 的状态。若原卡要求未满足，不写已验收。

交付：
用简短中文报告：修改的行为、文件、验证命令与结果、剩余限制、下一张可执行任务 ID。不要提交、推送、自动 reload 或实现下一张卡。报告已有无关失败时指出基线问题，不顺手修复。
```

## Luna 的推荐起步

第一次可把上面 A01 全部替换为 A03，完成 schema 局部修复；或选择 B05、C06、F01。C06 需要真实浏览器环境；没有环境时优先 A03/B05/F01。涉及状态机、durability、fencing、输出游标和 credential 刷新的任务留给 Sol。

## 每次交接的最小摘要

```text
已处理任务：<ID>
状态：<已验收 / 已实现待验证 / 阻塞>
修改文件：<列表>
实际验证：<命令、结果、skip、证据级别>
证据：<docs/verification/...>
未解决：<具体问题或无>
工作区注意：<已有改动及本次新增范围>
下一张建议：<已满足依赖的 ID>
```

执行模型发现卡与当前实现冲突时，先给出具体符号、当前行为、卡要求、最小兼容方案。普通实现细节自行处理；涉及改变已固定决策时停止该分支并说明冲突，不自行重写整份计划。
