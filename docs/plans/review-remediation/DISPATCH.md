## 创建与交接门槛

每次只请求创建一个任务，必须确认正式 threadId、worktree 目录存在、HEAD 正确、初始就绪响应后，才创建下一个。只有 clientThreadId 时保持“创建中”，不继续连发创建请求。无法确认时停止调度并报告具体状态，不自动重试造成重复任务。

先由集成工作准备包含既有未提交项目改动与计划的可追溯基线，验证后分配给开发。不得从裸 HEAD 开发而遗漏当前行输入等实现；不得把未验证基线自动推到 main。

开发完成后先记录分支、commit SHA、验证证据，再交集成工作。只有提交已经被集成分支引用或有可验证备份，才允许回收对应环境。不要让唯一成果只存在于 detached HEAD 或临时目录。

集成工作作为唯一 main 推送者，串行同步远端、合并、验证、正常推送；不强推。环境缺失和跳过测试均不得标已验收。每轮释放名额后才从满足依赖的卡中选择下一项。

恢复后的首批建议：Sol A01 与 Luna A03，两者无前置依赖；在实际创建状态稳定前不启动后续卡。

## 被清理时

官方文档说明受管理 worktree 默认保留最近 15 个，可配置；自动删除前保存快照，重新打开关联任务时提供恢复入口。固定聊天、运行中聊天和 permanent worktree 有相应保护。具体本机设置与某次清理原因仍需实查，不能仅凭提示断言是磁盘已满。

对有成果的任务优先通过该任务的恢复入口恢复并核对 git 状态/commit；只恢复当前要继续的一个，不一次恢复全部。对仅预建、没有改动的任务，不需要重建几十个工作树。不要为容纳队列而关闭全局自动清理。
